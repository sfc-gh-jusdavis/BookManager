# Plan: Unified ACE Agent + Documentation Links + User Preferences

## Overview

Three features delivered together:

1. **Unified ACE** — one chat interface that routes across BookManager data, sales intelligence, and code assistance automatically per message.
2. **Documentation hyperlinks** — ACE searches a curated docs catalog and returns clickable `[Title](URL)` markdown links inline in responses.
3. **User settings page** — accessible by clicking the username in the bottom-left sidebar; stores email greeting/closing preferences and writing style samples.

---

## Architecture: Why CORTEX.COMPLETE (not Cortex Agents REST API)

The SPCS backend connects to Snowhouse (`sfcogsops-snowhouse-aws-us-west-2`). In the previous session it was confirmed that `/api/v2/cortex/agents:run` returns `404` on Snowhouse — only `SNOWFLAKE.CORTEX.COMPLETE` via SQL is available.

The unified agent therefore uses a **3-phase pipeline** inside a single `POST /agent/chat` call:

```
flowchart TD
    UserMsg["User message"] --> Intent["Phase 1: Intent Detection\nPython keyword classifier\nzero latency"]
    Intent --> |needs_data| Analyst["Cortex Analyst\nbookmanager_assistant.yaml"]
    Intent --> |needs_docs| DocsSearch["Docs Search\nBKMNG_DOCS_CATALOG SQL ILIKE"]
    Intent --> |is_email| UserPrefs["User Preferences\nBKMNG_USER_PREFERENCES"]
    Analyst --> Synth
    DocsSearch --> Synth
    UserPrefs --> Synth
    AccountCtx["Account Context\nget_bookmanager_context()"] --> Synth
    Synth["Phase 3: CORTEX.COMPLETE\nllama3.1-70b synthesis\nunified ACE persona"] --> SSE["SSE stream\nto frontend"]
```

Phase 1 is Python keyword matching (no extra Snowflake call). Phases 2 run in parallel via `asyncio.gather`. Phase 3 is a single synthesis COMPLETE call. Total latency is the same as before.

## Task 2: Unified Agent Pipeline (`backend/app/routers/agent.py`)

Replace the `mode`-based routing with intent-driven unified routing.

### 2a. Intent detection (Python-level, no LLM call)

```
def _detect_intent(question: str) -> dict[str, bool]:
    q = question.lower()
    return {
        "needs_data": any(w in q for w in [
            "how many", "list", "show", "count", "accounts", "use case",
            "consumption", "revenue", "pipeline", "which", "who", "what stage"
        ]),
        "needs_docs": any(w in q for w in [
            "how do i", "how to", "documentation", "docs", "best practice",
            "guide", "learn", "setup", "configure", "what is", "explain"
        ]),
        "is_email": any(w in q for w in [
            "email", "draft", "write an update", "status update", "message to"
        ]),
        "is_code": any(w in q for w in [
            "sql", "query", "python", "snowpark", "code", "script",
            "write a select", "dbt", "stored procedure"
        ]),
    }
```

### 2b. Parallel tool dispatch

```
async def _run_tools(question, data, intent, account_id, ace_filter, user_id):
    tasks = []
    if intent["needs_data"] or not any(intent.values()):
        tasks.append(asyncio.to_thread(data.call_cortex_analyst, question, ace_filter, account_id))
    else:
        tasks.append(asyncio.coroutine(lambda: {})())
    
    if intent["needs_docs"]:
        tasks.append(asyncio.to_thread(data.search_docs, question))
    else:
        tasks.append(asyncio.coroutine(lambda: [])())

    if intent["is_email"]:
        tasks.append(asyncio.to_thread(data.get_user_preferences, user_id))
    else:
        tasks.append(asyncio.coroutine(lambda: None)())

    return await asyncio.gather(*tasks, return_exceptions=True)
```

### 2c. Synthesis prompt construction

The synthesis prompt assembles all available context and gives ACE explicit instructions for each type of response:

- For data queries: "List results by name. The SQL confirms the data matches."
- For docs: "Cite relevant docs as markdown links `[Title](URL)`."
- For emails: "Use the user's preferred greeting '{greeting}', closing '{closing}', and sign as '{ace\_signature}'."
- For code: "Format code in triple-backtick blocks with language label."

The `mode` parameter on `ChatRequest` is **kept for backward compatibility** (the floating `ACEChat` widget passes `mode: "bookmanager"`) but all modes now go through the same unified pipeline. The `"cortex_code"` model fallback chain (`claude-3-5-sonnet → mistral-large2 → llama3.1-70b`) is applied when `is_code` is detected.

### Remove `_stream_cortex_code()` and `_stream_agent()` separate paths

Both collapse into `_stream_unified_agent()`. The `mode` field on `ChatRequest` becomes effectively a hint rather than a hard router.

## Task 3: User Preferences Backend

### New file: `backend/app/routers/user.py`

```
router = APIRouter(prefix="/user", tags=["user"])

@router.get("/preferences")
async def get_preferences(user: CurrentUser = Depends(get_current_user), data = Depends(get_data_service)):
    return data.get_user_preferences(user.user_id)

@router.put("/preferences")
async def update_preferences(body: PreferencesUpdate, user: CurrentUser = Depends(get_current_user), data = Depends(get_data_service)):
    return data.update_user_preferences(user.user_id, body)

@router.post("/writing-samples")
async def submit_writing_samples(body: WritingSamplesRequest, user: CurrentUser = Depends(get_current_user), data = Depends(get_data_service)):
    # Calls CORTEX.COMPLETE to generate style_summary from samples
    style_summary = data.analyze_writing_style(body.samples)
    data.update_user_preferences(user.user_id, {"writing_samples": body.samples, "style_summary": style_summary})
    return {"style_summary": style_summary}
```

### New service methods in `snowflake_service.py`

- `get_user_preferences(user_id) -> dict` — SELECT from `BKMNG_USER_PREFERENCES`
- `update_user_preferences(user_id, prefs) -> None` — MERGE INTO `BKMNG_USER_PREFERENCES`
- `search_docs(question) -> list[dict]` — SELECT top 5 from `BKMNG_DOCS_CATALOG` WHERE tags/description ILIKE any word in question
- `analyze_writing_style(samples: list[str]) -> str` — calls `CORTEX.COMPLETE('llama3.1-70b', ...)` with a "analyze writing style" prompt, returns 2-3 sentence style summary

### Register in `main.py`

```
from app.routers import ... user
app.include_router(user.router)
```

## Task 6: Frontend Hooks + API Wiring

**`bkmng-next/hooks/useApi.ts`** — Add:

```
export function useUserPreferences() {
  return useQuery({ queryKey: ["user-preferences"], queryFn: () => apiFetch("/api/user/preferences") });
}

export function useUpdateUserPreferences() {
  return useMutation<unknown, unknown, PreferencesUpdate>({
    mutationFn: (body) => apiFetch("/api/user/preferences", { method: "PUT", body: JSON.stringify(body) }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ["user-preferences"] }),
  });
}

export function useSubmitWritingSamples() {
  return useMutation<{ style_summary: string }, unknown, { samples: string[] }>({
    mutationFn: (body) => apiFetch("/api/user/writing-samples", { method: "POST", body: JSON.stringify(body) }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ["user-preferences"] }),
  });
}
```
